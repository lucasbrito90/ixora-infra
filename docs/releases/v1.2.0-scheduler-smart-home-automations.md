## Release summary

This release delivers **Scheduler + Smart Home Automations** — time-based scheduling composed with Smart Home device actions already attached to vibes, without a separate automation engine.

| Phase | Deliverable |
| --- | --- |
| Backend execution | `VibeSmartHomeDispatchService` wired into `DispatchDueSchedulesCommand` post-commit |
| Domain validator | `ScheduleAutomationValidator` — ownership chain, no Policies in background |
| Mobile UX | Automation badges, schedule/vibe summaries, enriched API resources |
| Notifications | Push/local alignment; failure-only push; UX copy improvements |
| Operational readiness | Runbook, logging, failure matrix |
| E2E QA | Automated backend/frontend QA (Phase 8) |
| Appium validation | Real-device Android E2E (Phase 8.5) |

**Architecture:** ADR-022 through ADR-027. No new `automations` table. No server-side audio autoplay.

## Deployment notes

### Staging (already promoted via `develop` → `staging`)

1. Merge `main` back into `staging` after release if policy requires staging to track production tags.
2. Verify workers per [scheduler-smart-home-operational-checklist](../operations/scheduler-smart-home-operational-checklist.md):
   - Scheduler: `php artisan schedules:dispatch-loop`
   - Queue: `php artisan queue:work --queue=push,smart-home,default --tries=3 --sleep=3 --timeout=90`
3. Confirm `PUSH_PROVIDER=fcm` and Firebase credentials on App Platform.
4. Deploy mobile staging APK built with `npm run build:staging`.

### Production

- Deploy API + workers after staging sign-off.
- No database migrations required for this feature (composition model only).
- Mobile: publish Android build from tagged `front_vibes` commit.

**Do not** run `tofu apply` or production deploy without explicit approval.

## Rollback notes

| Layer | Rollback action |
| --- | --- |
| **API / workers** | Redeploy previous `main` tag; Smart Home dispatch hook is additive — rollback removes scheduler-triggered SH enqueue |
| **Mobile** | Ship previous APK; enriched API fields are optional on client |
| **Database** | No schema rollback required |
| **Push / notifications** | No new notification types — existing failure events unchanged |

If Smart Home dispatch causes operational issues post-release: disable is not feature-flagged — rollback deploy is the primary mitigation. Validator skip path is safe (log + continue, no push).
