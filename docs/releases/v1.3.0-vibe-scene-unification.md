# v1.3.0 — Vibe/Scene Unification (Phase 2)

**Release tag:** `v1.3.0-vibe-scene-unification`  
**Date:** 2026-09-02  
**Feature:** `vibe-scene-unification/phase-2`

**Complements:** [v1.3.0-smart-home-scenes.md](./v1.3.0-smart-home-scenes.md) (Phase 1, T01–T09). This document does not replace that release note.

---

## Release summary

Phase 1 (T01–T09) introduced **Scenes** as a standalone Smart Home resource. Phase 2 unifies Vibe and Scene: **`VibeDeviceAction` was a narrower, non-reusable variant of what Scene already provides** (inline actions tied to a single Vibe play path). The product decision was to **replace it entirely** and center Smart Home execution on **Scene**, with Vibe optionally referencing a Scene via **`scene_id`** (nullable, `nullOnDelete`, intentional reuse across multiple Vibes).

After this phase:

- Touching a Vibe (manual dispatch or scheduled) runs **`SceneActionJob`** for actions on the **linked Scene**, not `VibeDeviceAction` / `SmartHomeActionJob`.
- Schedule automation badges (`device_actions_count` / `has_device_actions`) reflect **Scene action counts**; API field names are unchanged for mobile compatibility.
- The legacy **`/api/vibes/{vibe}/device-actions*`** API and mobile device-actions UI are **removed**.
- **No data migration:** Scenes/Vibes were not yet in production; `vibe_device_actions` was dropped without preserving rows (explicit cutover at the start of Phase 2).

| Phase | Deliverable |
| --- | --- |
| T10 — Product decisions | Scene ↔ Vibe/Scheduler integration questions resolved (see [Known limitations](#known-limitations)); unification approach locked before implementation |
| T11 — Vibe ↔ Scene link | `vibes.scene_id` nullable FK → `scenes`, `Vibe::scene()`, `VibeResource`, store/update validation with ownership check |
| T12 — Dispatch repoint | `VibeSmartHomeDispatchService` and scheduled dispatch use linked Scene actions → `SceneActionJob`; failure push uses `smart_home_scene_action_failed` (`scene_id`, not `vibe_id`) |
| T13 — Schedule badges | `ScheduleResource` / `ScheduleController` count Scene actions via `vibe.scene.actions`; contract `device_actions_count` / `has_device_actions` preserved |
| T14 — Remove legacy path | Drop `vibe_device_actions` table; remove `VibeDeviceAction`, `SmartHomeActionJob`, device-actions API, `SmartHomeActionFailedNotification`; `SceneActionJob` is the sole Smart Home action job |
| T15 — Mobile unification | Scene picker on Create/Edit Vibe, link to manage scene actions; remove Vibe device-actions pages, service, composable, route |

**Architecture:** One execution path (`SceneActionJob`) for manual Vibe dispatch, scheduled Vibe dispatch, and direct Scene execute. A Scene may be shared by multiple Vibes or executed with no Vibe context — notifications and telemetry use **`scene_id`**, not an inferred `vibe_id`.

## Known limitations

| ID | Limitation | Impact |
| --- | --- | --- |
| **Staging only** | Not promoted to `main`/production | Operator approval required for production release |
| **Notification contract change** | `smart_home_action_failed` (payload with `vibe_id`) replaced by **`smart_home_scene_action_failed`** (payload with **`scene_id` only** — never `vibe_id`; Scene may be shared or executed without Vibe context) | Mobile does not yet handle `smart_home_scene_action_failed` specifically; informational only, not a staging blocker |
| **No data migration** | Existing `vibe_device_actions` rows were not preserved | Acceptable — pre-production cutover; no production users affected |
| **T10 decisions closed** | Original T10 card listed integration questions (Scene ↔ Vibe/Scheduler); all resolved in this phase | See Phase 2 deliverables; no open T10 blockers for staging |

**Product blockers:** None for staging use.

1. **`back_vibes`:** push to `staging` → App Platform rebuilds API + queue worker. **Migrations required** (already applied on staging per operator console):
   - `2026_09_02_230449_add_scene_id_to_vibes_table`
   - `2026_09_02_232728_drop_vibe_device_actions_table`
2. **`front_vibes`:** staging mobile build (`npm run build:staging`) — manual/CI device pipeline; not App Platform hosted.
3. **Queue worker:** unchanged — `SceneActionJob` on `smart-home` queue (sole action job after T14).
4. **Breaking API removal:** `/api/vibes/{vibe}/device-actions*` returns **404**; clients must use Scene actions + `vibe.scene_id`.
5. **No `ixora-infra` OpenTofu changes** required for this phase.

- **Not applicable** — this phase has not been promoted to `main`. Do not deploy to production until explicitly approved.
