**Release tag:** `v1.4.0-multi-provider-smart-home`  
**Date:** 2026-09-05

## Release summary

This release delivers **multi-provider Smart Home infrastructure** end-to-end: a config-driven adapter registry, descriptor API for dynamic mobile connection forms, device capabilities with sync-time persistence and dispatch gate, per-action execution logging with aggregate read API, retry-effective queue jobs, multi-provider telemetry, and regression coverage proving business layers stay provider-agnostic.

Home Assistant remains the **only production adapter**. Extensibility is proven by a **test-only fake provider** (no external I/O, never in committed production config).

## Known limitations

| ID | Limitation | Impact |
| --- | --- | --- |
| **Production adapter** | Home Assistant only | Fake provider is test-only; no commercial platform adapter ships in v1.4.0 |
| **T19 cancelled** | No cross-provider duplicate detection | Multi-instance HA users see separate device rows per connection — by design ([ADR-035](../decisions/ADR-035-cross-provider-deduplication.md)) |
| **Telemetry fallbacks** | Unmapped provider slugs → `Future`; unknown device types → `Other` | Provider works; dashboards lose granularity until telemetry enums updated |
| **Capabilities fail-open** | `capabilities: null` bypasses gate | Legacy/pre-sync devices behave as v1.3.0; full gate activates after sync with derivable capabilities |
| **Staging promotion** | v1.4.0 not yet on staging API | Mobile E2E against staging blocked for provider-types until operator merges `develop` → `staging` |
| **T28/T29 pending** | Documentation + extensibility diff gate | Provider operator guide and T29 checklist validation in progress |

**Product blockers:** None for `develop` integration testing. Staging mobile E2E blocked on API promotion.
