## Release summary

This release delivers **Smart Home Scenes** end-to-end on staging: a user-owned Scene resource with ordered device actions, manual execution that enqueues `SceneActionJob` work on the `smart-home` queue, dispatch telemetry, and a complete mobile UX (CRUD, action management with reorder, execute with result toast).

| Phase | Deliverable |
| --- | --- |
| T01 — Domain model | `scenes` / `scene_actions` tables, models, policy, factories |
| T02 — Scene CRUD API | `SceneController`, `SceneResource`, ownership via `findOwnedScene()` → **404** cross-user |
| T03 — Scene actions + reorder | Nested CRUD under `/api/scenes/{scene}/actions`, `POST .../reorder` |
| T04 — Manual execution | `POST /api/scenes/{scene}/execute`, `SceneDispatchService`, `SceneActionJob` |
| T05 — Dispatch telemetry | `SmartHomeDispatchEntryPoint::SceneManual`, wrapped in `SceneDispatchController` |
| T06 — Mobile Scene CRUD | `scene.service.ts`, `useScenes`, list/create/edit pages, Home entry point |
| T07 — Mobile scene actions | `scene-device-action.service.ts`, reorder (up/down), modal create/edit |
| T08 — Mobile execute | `scene-dispatch.service.ts`, Execute button + per-card loading + dispatch toast |
| T09 — QA + release | `SceneLifecycleIntegrationTest` (full lifecycle + cross-user 404 narrative), this release note |

**Architecture:** Scenes mirror the Vibe device-action pattern with deliberate isolation (ADR-023-style duplication). Execution is fire-and-forget at the API boundary — jobs run asynchronously against Home Assistant; the mobile Execute flow surfaces dispatch counts only, not per-action HA outcomes.

## Known limitations

| ID | Limitation | Impact |
| --- | --- | --- |
| **Staging only** | Not promoted to `main`/production | Operator decision required for production release |
| **Execute response** | API returns `dispatched` / `skipped` counts only — not which actions skipped or why | Mobile toast shows summary only; no per-action skip UI (by design) |
| **Async HA execution** | `POST .../execute` enqueues jobs; HA actuation success/failure is out of band | User confirms enqueue via toast; job outcome via existing Smart Home observability/push paths |
| **T10 pending** | Scene ↔ Vibe/Scheduler integration not decided | Scenes are standalone; no schedule trigger or vibe-play coupling yet |

**Product blockers:** None for staging use.

## Deployment notes

### Staging (already promoted via `develop` → `staging`)

1. **`back_vibes`:** push to `staging` → App Platform rebuilds API + queue worker (same image). Run migrations if not already applied (`scenes`, `scene_actions` tables from T01).
2. **`front_vibes`:** staging mobile build (`npm run build:staging`) pointed at staging API — not hosted on App Platform; manual/CI device pipeline.
3. **Queue worker:** must consume `smart-home` queue for `SceneActionJob` (same worker as existing Smart Home jobs).
4. **No `ixora-infra` OpenTofu changes** required for this feature.

### Production

- **Not applicable** — this release has not been promoted to `main`. Do not deploy to production until explicitly approved.
