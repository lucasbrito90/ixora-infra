IXORA Ecosystem — Product & Architecture Review

Data: 7 de junho de 2026  |  Escopo: front_vibes, back_vibes, ixora-admin, ixora-infra  |  Método: Análise read-only (sem alterações de código)

1. Executive Summary

IXORA é uma plataforma de áudio ambiente funcionalmente madura no Android, com um loop central pronto para produção: Firebase auth → sync Laravel → CRUD de vibes → plano de execução → playback nativo → download offline. O stack de catálogo/admin (sounds, covers, preset vibes) e a infraestrutura de staging estão substancialmente implementados.

Desde o baseline de 2 de junho de 2026, as maiores melhorias foram:

  • Backend confidence sprint — testes de Vibe e VibeSound API (~150 casos Pest, antes 104)
  • CI quality gates — quality.yml nos 3 repositórios de app
  • Catálogo de sounds escalável — search, filters, sort, pagination no backend + admin

A plataforma não está pronta para produção nem para automação Scheduler end-to-end. O Scheduler existe apenas como stubs de banco + docs de planejamento.

Scheduler MVP: GO condicional — iniciar spec/ADR + Schedule CRUD no backend; NO-GO para playback automatizado completo sem FCM e UI mobile.

14. Bottom Line

IXORA tem uma base sólida de playback ambiente adequada para iniciar CRUD de Scheduler no backend e trabalho de especificação. O Scheduler MVP completo com wake-and-play automatizado requer FCM, worker runtime, UI mobile e ADRs — hoje ~18% dos pré-requisitos estão completos.
